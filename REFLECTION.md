### Module 12 Reflection

Integrating authentication and calculation routes with the existing models required linking users to their calculations so operations stay scoped to the right account. Building on the Pydantic schemas and database logic from Modules 10–11, request and response schemas validated incoming payloads and shaped clean API outputs while SQLAlchemy sessions and database initialization handled persistence across routes.
Securing these endpoints relies on password hashing (via bcrypt) for credentials, JWT bearer tokens for authentication, and dependency checks that verify the authenticated user before allowing access to protected calculation routes.
Running pytest alongside Docker and PostgreSQL helps keep those endpoints reliable as code changes. Testing against a real database service rather than relying solely on manual Swagger UI clicks catches startup race conditions, environment mismatches, and integration issues early. Working through container startup ordering, 401 unauthorized responses, and sys.path behavior when running uvicorn from the project root reinforced how closely application structure, configuration, and testing tie together.
This module shifted my focus from isolated models and scripts to how authentication, database state, and container environments interact under real requests. Moving forward, I want to keep my local and containerized configurations aligned early so debugging takes less trial and error.
